# FloatChat

A source-linked ocean investigation workspace. The workspace combines a historical May 2025 seed with on-demand GDAC updates for three tracked INCOIS floats. The verified refresh on 20 September 2026 contains 45 real profiles, with observations through 16 September 2026.

See [the requirements audit](docs/requirements-audit.md) for requirement status, measured offline performance, remaining gaps and current event submission constraints. The 41-page original blueprint is a proposal, not a list of implemented components.

## Implemented

- Reproducible NetCDF acquisition, SHA-256 manifests, mode-aware raw/adjusted selection.
- A read-only FastAPI profile catalogue, depth/QC selection, and evidence export.
- React workspace with an offline geographic basemap, selectable observed positions, time cutoff, float/cycle search, depth charts and a source evidence drawer.
- Quality filtering, explicit empty/error states, pressure-to-depth conversion with TEOS-10 GSW, and original profile/level identities.
- ZIP export containing exact filtered measurements as CSV and a complete JSON evidence record.

This is a cached observation snapshot with on-demand updates, not a continuous live feed. Multi-profile queries, optional Gemini/Groq/OpenAI query adapters with local fallback, Cesium 3D/time exploration, exploratory gradients and visual profile comparisons are implemented. Observed time-depth cross-sections and gap-aware gradient sections are implemented. Monthly WOA23 climatology departures, ranked review and printable evidence reports are implemented and verified on the bounded dataset. Daily marine-heatwave detection, multimodal input and forecasting remain unimplemented. Live AI verification requires server-side credentials; simulated-provider tests are not a language-understanding benchmark.

## Multi-profile queries

Use **Ask the ocean → Interpret → review filters → Run query**, or enter filters directly. Without AI credentials, interpretation uses the explicit local grammar. With server-side configuration, the OpenAI Responses API proposes a validated plan; the visible engine label identifies the actual mode. Review the filters before executing.

Supported examples:

- `Show temperature and salinity between 200 and 1000 metres in May 2025`
- `Now show salinity only` (inherits other visible filters)
- `Show float 1902676 from 2025-05-03 to 2025-05-13`
- `Show all floats in May 2025`

The manual form supports multiple float IDs, inclusive UTC dates, a depth interval, temperature/salinity, QC policy and rectangular geographic bounds. West greater than east selects across the dateline. Empty float selection means all floats in the snapshot. The Indian Ocean phrase uses the disclosed rectangular preset 20–120°E, 60°S–30°N.

`POST /api/interpret` returns a candidate plan or clarification. `POST /api/query` validates and executes that same plan. `POST /api/query/export` produces a ZIP containing all matching observations and evidence. Scientific values are computed from the snapshot, never generated by the interpreter. Plans bind to a snapshot; stale snapshots and unknown floats are rejected. No results are silently truncated (maximum 100 matching profiles).

Query results drive the observation list, map and selected profile charts. Per-profile evidence retains original source/level identity. The query export includes profile IDs and source filenames alongside every row. Date/depth/QC changes in the draft do not change a completed result until Run query is pressed; the interface labels that state.

## Quick start

Requires Python 3.12+ and Node.js 22+. Run from the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
cd frontend
npm ci
cd ..
.\.venv\Scripts\python.exe -m backend.ingestion
.\scripts\start.ps1
```

Open http://127.0.0.1:5177. Interactive API documentation is at http://127.0.0.1:8017/docs. Vite forwards `/api` to the local backend. Both bind to the loopback interface. Dedicated ports avoid interfering with other local development apps.

For foreground terminals, use `scripts/start.ps1 -Service api` and `scripts/start.ps1 -Service web` separately. The combined start command launches hidden background processes and prints their process IDs; logs go to `artifacts/`. Stop the printed process IDs when finished. Avoid launching another copy while those ports are in use.

On this machine the global npm shortcut was broken; `& 'C:\Program Files\nodejs\npm.cmd' ci` works. A project-local `.venv` and installed frontend dependencies have already been prepared. If a restrictive Windows sandbox prevents esbuild from reading the Vite config, run the development/build command from a normal local terminal with access to this project.

After the initial ingestion, `python -m backend.ingestion --offline` rebuilds from cached, checksum-verified NetCDF files. Normal exploration reads the cache; the explicit Check for new profiles action downloads updated source files. Fonts have system fallbacks if the font host is unavailable.

## Data and scientific choices

The ingestion source list is fixed in `backend/ingestion.py`; source URLs and content checksums are in `data/manifests/demo.json`. Raw files and processed observations are excluded from Git. Data are provided by Argo GDAC / INCOIS; cite [Argo DOI 10.17882/42182](https://doi.org/10.17882/42182).

- Mode R selects raw variables. Modes A/D select adjusted variables. Missing adjusted values never fall back silently to raw values.
- Default accepts QC 1; exploratory selection accepts QC 1 and 2. Pressure, position and time must meet policy; temperature and salinity are independently masked.
- Positive-down depth uses `-gsw.z_from_p(pressure, latitude)` without a dynamic-height correction. Pressure (dbar) and depth (m) remain separate fields.
- Salinity is practical salinity on PSS-78, dimensionless. Temperature is the source in-situ temperature in degrees Celsius.
- All samples retain zero-based NetCDF profile/level indices. No interpolation or scientific resampling is performed. Chart lines connect samples and break at missing variable values. Dashed map lines do not assert a measured underwater trajectory.
- Results include snapshot, method, normalized selection and stable identity. Exports contain the same result as the visible filtered charts.

## Architecture and next steps

For this nine-profile slice, a versioned JSON snapshot keeps setup small and the scientific contract inspectable. It is a deliberate initial adapter, not the proposed large-scale Zarr/PostGIS implementation. No Docker/database server is required yet.

1. Move prepared arrays to Zarr and discovery to PostGIS behind the existing API contract.
2. Configure and evaluate the optional AI planner on real questions; preserve the local parser and manual controls as fallbacks.
3. Expand the observed cross-sections with scientifically validated spatial analysis once data coverage supports it.
4. Add compatible climatological reference data, daily-SST heatwaves, and robustness variants.

Keep the first working path intact: source file → quality-aware result → linked views → reproducible export.

## 3D exploration and observation replay

Choose **3D**, then **Dive into profile**. Switch temperature/salinity, choose a labelled depth exaggeration (1, 100 or 300), and use the observed-level slider to open original sample evidence. Replay steps through exact observation timestamps, keeping future profiles hidden; Show all restores the selected set. Query exports always contain the full query result, regardless of replay position.

Cesium uses locally served assets and Natural Earth land outlines, without a map-service key. The basemap is an ellipsoid, not bathymetry. Depth samples are anchored at the profile position; individual underwater locations are not measured. Dashed paths connect recorded profile positions, without asserting measured intermediate movement. Color scales are fixed and clipped at their labelled limits. This is historical observation replay, not a forecast.

Cesium loads on demand (~1.14 MB gzip JavaScript plus runtime assets). WebGL failures offer the 2D map. Run frontend logic checks with `npm run test` from `frontend` using Node 22.6+ (validated on Node 24); build with `npm run build`.

## Profile science lab

The science lab computes exploratory finite differences between consecutive source levels, accepting depth spacing from 2 m to a selectable maximum (25/50/100 m). Missing values, QC-excluded source indices and large gaps break calculations. The thermocline candidate is the strongest negative temperature gradient in the selected depth band; it is not a validated boundary or a mixed-layer-depth estimate. Salinity reports the signed gradient of greatest magnitude. Background: https://oceanservice.noaa.gov/facts/thermocline.html. The numerical heuristic and gap settings are FloatChat design choices, not a NOAA-prescribed detection method.

Pin the current result, select another profile, and compare observed samples within 1/5/10 m depth tolerance. Matching is greedy, shallow to deep, nearest unused reference sample (source index resolves ties); it is not an optimal assignment or interpolation. The table reports both actual depths, signed depth offset and current-minus-reference values. Both sides link to their own source evidence. Changing QC, snapshot or processing method prevents incompatible comparisons. Pinned references remain fixed when filters change. Export analysis JSON includes both full source-linked input results, selected parameters, calculated gradients and paired differences. Location/date differences preclude interpreting these differences as a climate trend.

### Visual profile comparison

Pinned comparisons include overlaid observed markers and paired differences plotted at current sample depths. Markers intentionally do not connect through unobserved water. Both overlay series open their own evidence; difference points open current evidence, with both sources available in the table. The layout stacks charts on mobile.

Comparison context reports spherical great-circle separation of the reported locations (mean Earth radius 6371.0088 km) and signed timestamp difference in days. This is endpoint separation, not distance travelled by a float. The JSON analysis export includes this context. It does not establish a climate anomaly or temporal trend.

## Optional AI query planner

Set `OPENAI_API_KEY` and `FLOATCHAT_AI_MODEL` in the backend process environment, using a model available to your account that supports Responses API structured outputs. `.env.example` documents the settings; it is not automatically loaded. Never put the key in frontend variables or source control. Restart the API from the environment containing these variables. Keep this local service bound to loopback; public deployment needs authentication and request/cost limits first.

`GET /api/assistant/status` reports configuration (not a successful provider connection). `/api/interpret` sends the question, visible query context and compact catalogue metadata to OpenAI; no raw samples or API key are included in the prompt. Responses use strict JSON schema and `store: false`. Each response has a generation ID; the provider response ID is returned when available. This version does not persist generation history or track usage costs.

Questions inherit the current visible filter plan, not arbitrary chat history. Model plans are checked by Pydantic and the same catalogue/resource validation used by manual queries. Snapshot changes and unknown floats cannot execute. Unsupported scientific requests should return clarification; this instruction still requires real-model evaluation. Provider/network errors explicitly fall back to the limited local parser. Invalid/refused/incomplete model output asks for rephrasing without changing the draft. The UI always requires Run query before updating observations. Numerical result summaries remain deterministic, not AI-generated.

API design reference: https://developers.openai.com/api/docs/guides/structured-outputs

## Groq activation (Windows)

Run `powershell -ExecutionPolicy Bypass -File .\scripts\start-groq.ps1` from the project folder in your own terminal. Paste the key only into its hidden prompt. The launcher keeps it in the backend process environment for that session, not in a file or shell command history. It replaces a verified existing FloatChat API on port 8017 and runs the API in the foreground; keep the terminal open. Refresh the app afterwards. The configured label is not proof of a successful provider call: submit a question and check that the response explicitly says Groq rather than local fallback.

The default Groq model is `openai/gpt-oss-20b`; override with `-Model` for another strict-structured-output model available in your account. This is a Groq-hosted model; it does not require an OpenAI key. Groq uses `https://api.groq.com/openai/v1/chat/completions`, with the same local query validation and fallback as the OpenAI adapter. Environment configuration: `FLOATCHAT_AI_PROVIDER=groq`, `GROQ_API_KEY`, optional `GROQ_MODEL`. Explicit provider selection never substitutes another provider's key. Without explicit selection, a Groq key takes precedence over OpenAI.

Reference: https://console.groq.com/docs/structured-outputs. No live Groq request has been verified yet; the key stays with the user until local activation.

## Gemini activation

Stop the existing Groq API task with Ctrl+C, then run `powershell -ExecutionPolicy Bypass -File .\scripts\start-gemini.ps1` from the project folder, or choose the Gemini hidden-key task in VS Code. Enter your Google AI Studio Gemini API key only in the hidden prompt. Keep the terminal open and refresh FloatChat. Default model: gemini-3.8-flash; use `-Model` to select another compatible model available in your account. Live account/model access remains unverified until activation.

Settings: FLOATCHAT_AI_PROVIDER=gemini, GEMINI_API_KEY and optional GEMINI_MODEL. The key is sent in the x-goog-api-key header to generativelanguage.googleapis.com, never as a URL parameter. Questions, filter context and public catalogue metadata are sent for structured interpretation; original measurements remain local. Blocked/incomplete outputs cannot become query plans. The same validation and explicit local fallback apply. Groq remains available as an optional provider; the launcher explicitly selects Gemini.

Reference: https://ai.google.dev/gemini-api/docs/generate-content/structured-output


## Observed depth cross-sections

Run a query using manual filters, then scroll below the science lab to Depth cross-section. Choose temperature or salinity, observed values or vertical gradients, and all queried floats or one float. The UTC time axis preserves irregular observation timing; the depth axis is positive down. This section always uses the full completed query, independently of map replay/search.

Observed markers retain their exact source values. Gradient diamonds sit at the interval midpoint and represent signed differences per metre between consecutive source levels, at least 2 m and at most the selected 25/50/100 m apart. No interpolation connects profiles or fills gaps. Positions change between observations, so this is not a fixed-location transect. Color scales adapt to the section; gradient scales are symmetric around zero.

Click a marker to inspect its original source level(s), or expand the profile inspection links for keyboard access to a profile's first available sample/interval. Each interval exposes both endpoints in the evidence drawer. Export section JSON retains the full source-linked profile results, query plan, filters, processing method and displayed points. The section is lazy-loaded and uses the existing Plotly bundle.


## Saved investigations

Open **Saved investigations** below the query filters. Name and save the current filter selection, then use **Load filters** to restore it. Loading does not execute a query or replace the existing result; review the form and press **Run query**. Bookmarks are stored only in this browser, with a maximum of 20. Browser data clearing removes them, so use **Export bookmarks** for a portable JSON backup. **Import bookmarks** appends validated entries and gives them new local identities.

Only names, save timestamps and query plans are stored. Measurements, questions and API credentials are excluded. Different snapshot identities and unavailable floats prevent loading. Imports reject invalid dates, depths, coordinates, variables, unsupported versions and files larger than 200 KB. A detected change from another tab stops a stale write and asks you to refresh. Corrupt or inaccessible storage shows an error without silently overwriting existing content. This is a local filter library, not account synchronization or an archive of result data.


## Investigation reports

After **Run query**, choose **Download report** in the result actions. Open the downloaded HTML file in a browser; it is self-contained, script-free and readable offline. Browser Print can save it as PDF. Reports contain the executed query filters, observed ranges and sample counts, per-profile coverage, source file links/checksums, methods, limits and reproducibility IDs. They cover the full completed query even when draft filters or map replay change. Empty results remain empty; stale snapshots are rejected. Pinned comparisons and gradients have their own exports and are not included. Download the query ZIP as well for exact measurements and complete evidence.

`POST /api/query/report` uses the same validated query execution as the data and ZIP endpoints. Display values are rounded; source hashes and the normalized query are retained exactly. External metadata is HTML-escaped and source links require HTTPS. No model call or external stylesheet is needed.


## On-demand GDAC refresh

Use **Check for new profiles** above the query panel. The app reads official GDAC directories for tracked floats 1902674/1902675/1902676 and downloads their latest three numbered ascent cycles, preferring a delayed-mode file when both R and D versions exist for the same cycle. It does not discover all Indian Ocean floats, backfill intervening cycles, or check revisions to older files outside that latest-cycle window. Checks are user-triggered; there is no scheduled polling or continuous telemetry.

Every batch reuses mode-aware NetCDF normalization and validates float, cycle and ascent identity. A failed batch leaves the published snapshot untouched. A successful batch retains existing profiles, adds or replaces matching profile identities, archives the old snapshot under data/processed/history, and stores downloaded NetCDF files by SHA-256 in data/raw/refresh. No-change checks preserve snapshot identity. Limits: three listings (2 MB each), at most nine files (10 MB each), and 100 accumulated profiles. Snapshots include source URLs, hashes and acquisition times; data/manifests/demo.json continues to describe only the original seed.

The status distinguishes last-check time from latest observation time. Click **Reload updated data** after publication; draft filters and unsaved results reset on reload, while saved bookmarks remain in browser storage. Old bookmarks retain their original snapshot ID and cannot silently run against new data. Real-time R values carry a preliminary-quality note and may be revised later. Argo recommends delayed-mode data for applications sensitive to small salinity/pressure biases: https://argo.ucsd.edu/data/how-to-use-argo-files/.

Endpoints: GET /api/data/status, POST /api/data/refresh with X-FloatChat-Refresh: 1. This local-only implementation uses one API worker and an in-process lock; do not run concurrent CLI ingestion/refresh processes or deploy multiple workers. Standalone CLI: python -m backend.refresh when the API is stopped. Running backend.ingestion again restores the fixed historical seed; it does not reconstruct the expanded refresh cache. Official access overview: https://argo.ucsd.edu/data/data-from-gdacs/.


## Quality and sampling coverage

After Run query, expand **Quality and sampling coverage** below the results. The audit includes every profile matching the float/date/geographic filters, including those with no usable samples. Each source level is assigned exactly one reason in order: position/time QC exclusion; pressure QC or unavailable depth; outside requested depth; no usable requested variable; retained. Depth filtering is not labelled as bad quality. Temperature and salinity are audited independently after the first three filters, with missing taking precedence over variable QC exclusion.

The panel lists real-time/adjusted/delayed profile counts and per-float first/last retained observations and maximum interval between distinct retained timestamps. These are coverage gaps in the cached query, not proof of missing transmissions. Historical seed plus latest-cycle refresh intentionally leaves intervening profiles undownloaded. The audit is tied to the executed result and included under quality in query evidence.json; it does not change with draft edits or map replay. Method: selection-audit-v1.


## Bounded recent history

The data-update panel now offers 3, 12 or 24 latest ascent cycles per tracked float (up to 9, 36 or 72 NetCDF files). Choose a window and click Download recent history. This is a cycle-count window, not a calendar duration or complete archive. Existing cached profiles are retained, so older gaps can remain. The 100-profile snapshot cap still applies; exceeding it rejects publication without silently dropping profiles. A real 12-cycle import on 2026-09-20 produced 45 total profiles (36 recent plus 9 historical seed profiles), latest observation 2026-09-16.

Progress is persisted after each validated file and polled by the interface, including after page reload. Browser imports execute NetCDF work in an isolated Python worker, with a 30-minute bound; worker failure is reported without crashing the API. Local worker stderr is recorded in artifacts/import-worker.log. Checks remain on demand, single API worker, with no concurrent standalone CLI imports. CLI (API stopped): python -m backend.refresh --cycles 12. The request parameter is POST /api/data/refresh?cycles=12; only 3/12/24 are accepted. Previously documented three-cycle scope remains the default, while the larger windows are optional.

## Depth-target time series

After Run query, choose a target depth and tolerance in Depth-target time series. One finite retained sample per profile is selected by nearest depth, with ties resolved by shallower depth then source level. The target must be within the executed query band; matching never retrieves samples excluded by that query. Float and variable filters apply only to this panel. The table includes unmatched profiles, actual depths, signed depth offsets and source evidence. JSON retains the query, all scoped input profiles and explicit nulls for unmatched samples. Markers have no connecting lines: varying depths and moving locations do not establish a fixed-site trend or climate anomaly.

## Monthly climatology departures

After Run query, open Climatology departures and Compare with climatology. The endpoint POST /api/query/anomalies accepts the executed plan and depth_tolerance_m (0–50). It compares retained temperature/salinity with NOAA WOA23 1991–2020 monthly objectively analyzed means (t_an/s_an), using the observation calendar month and containing 1-degree cell. The nearest standard depth must lie within the tolerance; ties prefer shallower depth. No annual substitution, masked-cell search, extrapolation, or additional interpolation occurs. Monthly fields extend to 1500 m; samples beyond the supplied depth range stay unmatched. This is a departure calculation, not heatwave detection, a statistical significance test, forecast or climate trend. WOA historical inputs can include Argo, so it is not independent validation.

Prepare reference files from the project terminal using `.venv\Scripts\python.exe -m backend.reference_import --archive ncar --months 5 6 7 8 9`. Downloads are public NOAA global 1-degree monthly files, two per month, bounded at 100 MiB each (roughly 500–600 MB for five months). The importer validates variable identity, units, month/period title, grid and depth structure; extracts only columns at current cached profile locations; records original-file SHA-256 and source URL; and atomically publishes data/reference/woa23.json after the entire requested batch validates. The NCAR GDEX archive is available with --archive ncar; NOAA remains the default without that option. NCAR raw files remain under data/reference/ncar, NOAA files under data/reference/raw. Up to four downloads run concurrently; NetCDF extraction remains serial. Evidence records both the original NOAA URL and the actual download archive URL. Run only one reference importer at a time. It does not change the Argo snapshot, and NetCDF parsing stays outside the API process. Repeat after adding new months or float locations. Missing cached columns remain explicitly unavailable.

For already downloaded official NOAA files, use `--files-dir C:\path\to\files` with the same months. Expected filenames are woa23_decav91C0_tMM_01.nc and woa23_decav91C0_sMM_01.nc. Imported metadata includes the import timestamp; this is not the original publication time. On failure the published reference cache remains unchanged. Once prepared, click Compare with climatology again; no API restart is required.

The UI and JSON export include all eligible observed values, match/exclusion counts, signed departures, actual/standard depths, spatial offsets, Argo evidence and WOA source hashes. UI variable filtering does not limit the exported evidence. Empty or unavailable baselines never become zero departures. Real reference data is installed: ten WOA23 files for May–September were obtained from NCAR GDEX after NOAA services timed out. Cache 60d00b8b5cd66e9d contains 340 columns at the current 34 cached profile cells. The full 45-profile query at ±25 m matched 5,873 variable values; each baseline value and departure was verified directly against its original NetCDF file, and all ten file hashes were checked. Another 1,480 values are outside the monthly reference depth range; none use a substitute baseline. Other months or new grid cells require another import. The diverging depth/time chart plots matched observations, blue below the monthly mean and red above it, with a symmetric adaptive scale; click a marker or use the sample selector to inspect both sources.

Official references: https://www.ncei.noaa.gov/products/world-ocean-atlas and https://www.ncei.noaa.gov/thredds-ocean/ncss/grid/woa23/DATA/salinity/netcdf/decav91C0/1.00/woa23_decav91C0_s01_01.nc/dataset.html

## Ranked departure review

Within Climatology departures, Review the largest departures filters matched samples by float, minimum absolute departure and above/below direction. The threshold is inclusive and expressed in the selected variable's units; switching variable resets it to zero. Results sort by descending absolute departure, with deterministic profile/source-level ties. The table shows at most 20 rows; Export ranked review includes every qualifying row, review parameters and the complete original analysis/source evidence. Review sources selects the matching Argo and baseline evidence. These controls do not filter the chart or full evidence export. Thresholds are user-selected review filters, not significance levels, event counts or marine-heatwave criteria.

## Printable climatology report

Browser Print can save it as PDF. It includes the exact query plan and IDs, baseline period/tolerance, match/exclusion counts, separately ranked top 20 departures per requested variable, interpretation limits, all baseline and Argo source links/hashes. The report covers the full calculated analysis regardless of chart selection or ranked-review float/sign/threshold filters. Rounded report values are for presentation; export departure evidence JSON alongside it for exact measurements and all source mappings.
